# Sicumi — спецификация и архитектура

> Копия из Claude Docs для AI-агентов. Живая (главная) версия: https://claude.ai/code/artifact/b97ffe60-96a2-4474-b11e-e306f5680bb2

Sep 27, 2026 · @Kosta

## Обзор продукта

Sicumi — бесплатное публичное мобильное приложение-ассистент для iOS и Android, полностью на иврите, с двумя модулями: протоколы встреч и голосовая диктовка в стиле Wispr Flow. Обе платформы пишутся нативно: SwiftUI на iOS, Kotlin + Jetpack Compose на Android. Только телефоны, без отдельной версии для планшетов.

**Модули**

1. **Протоколы встреч (פרוטוקולים)** — встроенный диктофон или загрузка готового аудиофайла → облачный STT → LLM → структурированный протокол.
2. **Голосовая диктовка (הכתבה)** — на iOS системная клавиатура, на Android плавающая кнопка поверх любых приложений, без своей клавиатуры. Нажал, продиктовал, нажал ещё раз — чистый текст на иврите вставляется в поле.

**Базовые принципы**

- Только иврит. Одна локаль `he`, других языков интерфейса нет. RTL — фундамент, а не опция.
- Интерфейс — такое же базовое требование, как RTL: современный, красивый, не шаблонный (раздел «Дизайн интерфейса»).
- Бесплатно. Расходы на распознавание и LLM идут на API-ключ пользователя (BYOK): он выбирает провайдера из готовых пресетов и вставляет свой ключ.
- Local-first с синхронизацией: данные живут на устройстве; по желанию — аккаунт и синхронизация между устройствами. API-ключи не синхронизируются.
- Публикация в App Store и Google Play с первого релиза: политика приватности, раскрытие данных, корректные разрешения.

## Модуль 1 — протоколы встреч

Пользователь нажимает одну кнопку, записывает встречу любой длины с заблокированным экраном и получает готовый протокол на иврите с решениями и задачами.

**Источники аудио**

- Запись встроенным диктофоном.
- Загрузка готового файла, записанного в другой программе: кнопка «ייבוא קובץ שמע» (выбор из файлов) или «Поделиться» из WhatsApp, диктофона телефона, почты, Zoom. Форматы: m4a/AAC, mp3, wav, ogg/opus (голосовые WhatsApp), mp4/mov (берётся звуковая дорожка).

Загруженный файл проходит тот же пайплайн, что и запись, начиная со шага 2. Если формат не принимается провайдером или файл длиннее его лимита, приложение перекодирует и нарезает его на устройстве.

**Пайплайн обработки**

1. Запись на устройстве: AAC (.m4a), моно, 16 кГц, 32–48 кбит/с — около 15–20 МБ на час. Файл пишется сегментами по 5 минут, чтобы сбой приложения не уничтожил всю запись.
2. Сохранение локально и постановка в очередь обработки. Без сети задача ждёт и стартует сама.
3. Загрузка в выбранный STT-провайдер в асинхронном режиме (фоновая загрузка системы), с включённой диаризацией.
4. Транскрипт с тайм-кодами и метками дикторов (דובר 1, דובר 2…). Пользователь может переименовать дикторов в имена участников.
5. LLM получает транскрипт + шаблон протокола + метаданные встречи и возвращает строгий JSON. Длинные встречи обрабатываются по частям с финальным объединением.
6. Приложение рендерит JSON в редактируемый протокол и отправляет локальное уведомление «הפרוטוקול מוכן».

Статусы задачи: `recorded` → `uploading` → `transcribing` → `summarizing` → `ready`; любой шаг может уйти в `failed` с кнопкой «נסה שוב». Транскрипт сохраняется отдельно, поэтому протокол можно пересоздать с другим шаблоном или другой LLM без повторной оплаты STT.

**Функции диктофона**

- Старт / пауза / продолжение / стоп, таймер, индикатор уровня звука.
- Запись с заблокированным экраном и в фоне; управление с экрана блокировки (Live Activity на iOS, уведомление с кнопками на Android).
- Закладки во время записи («חשוב») — метки времени, которые LLM учитывает как важные моменты.
- Корректная реакция на входящий звонок и отключение наушников: автопауза и продолжение в тот же файл.
- Предупреждение о малом свободном месте и низком заряде перед длинной записью.

**Структура протокола (черновик шаблона по умолчанию).** Будет приведена к образцу протокола в PDF, который пришлёт Kosta.

| Раздел | Заголовок в приложении | Содержание |
| --- | --- | --- |
| Шапка | פרטי הפגישה | Название, дата, время, место, длительность |
| Участники | משתתפים | Имена и роли |
| Краткое резюме | תקציר | 3–5 предложений |

**Экспорт:** PDF с RTL-вёрсткой, DOCX, копирование текста, системное меню «Поделиться» (WhatsApp, почта). Задачи можно отправить в системные напоминания / календарь.

## Модуль 2 — голосовая диктовка (аналог Wispr Flow)

Пользователь вызывает диктовку в любом поле ввода: на iOS — кнопкой микрофона на клавиатуре Sicumi, на Android — плавающей кнопкой поверх приложения. Он говорит естественно и получает чистый текст на иврите: без слов-паразитов, с пунктуацией и учётом самоисправлений. За основу взят набор функций [Wispr Flow](https://wisprflow.ai/features).

**Функции MVP**

- Режимы записи: нажатие — старт, повторное нажатие — стоп и вставка; удержание (push-to-talk) для коротких фраз.
- Предпросмотр текста во время речи, если провайдер поддерживает стриминг; иначе — запись целиком и быстрая отправка файла после стопа.
- AI-очистка: удаление паразитов (אממ, אה, כאילו), самоисправления («בשתיים… לא, בשלוש» → «בשלוש»), пунктуация, списки, числа и даты цифрами.
- Смешанная речь иврит + английские термины: английские слова остаются латиницей и корректно встраиваются в RTL-текст.
- Личный словарь (מילון אישי): имена, термины, аббревиатуры; передаётся в STT как контекст и в LLM как список написаний.
- Сниппеты (קיצורים): голосовая фраза → готовый текст (адрес, подпись, ссылка).
- Стили: «как сказал», «чисто», «формально», «сообщение». На Android стиль выбирается автоматически по приложению (имя пакета активного окна); на iOS — вручную.
- История диктовок в основном приложении — можно скопировать потерянный текст.
- Только iOS: базовая раскладка для набора (иврит, цифры, английский, смена клавиатуры) — её требуют правила App Store. На Android своей клавиатуры нет, пользователь остаётся со своей.

**После MVP:** командный режим (выделить текст и сказать «תקצר», «תרגם לאנגלית», «תנסח יותר מנומס»), автообучение словаря на исправлениях, шёпотный режим.

**iOS: клавиатура не может записывать звук.** Расширение клавиатуры не имеет доступа к микрофону ([Apple Developer Forums](https://developer.apple.com/forums/thread/800500)). Поэтому запись ведёт основное приложение в фоновом режиме audio, а клавиатура обменивается с ним через App Group. Так же работает Wispr Flow: клавиатура открывает приложение, пользователь возвращается свайпом вправо по нижнему краю ([Wispr Flow Help](https://docs.wisprflow.ai/articles/7453988911-set-up-the-flow-keyboard-on-iphone), [iOS 26.4](https://docs.wisprflow.ai/articles/6269634092-adapting-to-ios-26-4)). Требуется включение «Full Access» для клавиатуры.

> Диаграмма «диктовка через клавиатуру iOS · 5 шагов» — в живой версии документа.

Переход в приложение нужен только для запуска сессии; пока сессия активна (настраиваемо, например 5–15 минут), следующие диктовки идут без переключения. В системе при этом горит индикатор микрофона.

**Android: плавающая кнопка вместо клавиатуры.** Так же устроен Wispr Flow на Android: кнопка появляется, когда открывается клавиатура, а текст вставляется через Accessibility API ([кнопка и вставка](https://docs.wisprflow.ai/articles/2296441257-starting-your-first-dictation-on-android), [зачем разрешение](https://docs.wisprflow.ai/articles/7669452251-accessibility-permission-on-android)).

1. Пользователь ставит курсор в любое поле — рядом появляется кнопка Sicumi. Её можно перетащить; в полях паролей она не показывается.
2. Нажатие — звук старта и волна на кнопке, идёт запись.
3. Повторное нажатие — стоп, на кнопке индикатор обработки (STT → LLM-очистка).
4. Текст сразу вставляется в поле в позиции курсора. Если поле не принимает вставку — текст копируется в буфер и показывается уведомление «הועתק».

Технически: `AccessibilityService` отслеживает поле в фокусе, рисует кнопку окном `TYPE_ACCESSIBILITY_OVERLAY` и вставляет текст (`ACTION_PASTE` через буфер с восстановлением его содержимого или `ACTION_SET_TEXT`). Нужны разрешения: специальные возможности, микрофон, уведомления. В Google Play требуются декларация использования Accessibility API и заметное раскрытие в приложении с явным согласием ([Play Console Help](https://support.google.com/googleplay/android-developer/answer/10964491?hl=en)).

## Иврит и RTL как фундамент

Приложение всегда работает на иврите и в RTL, независимо от языка телефона. Телефон с английским интерфейсом — основной тестовый случай, потому что именно там RTL ломается чаще всего.

**iOS (SwiftUI)**

- В проекте единственная локализация `he`; `CFBundleDevelopmentRegion = he`. То же для расширения клавиатуры и виджетов (у каждого таргета свой бандл).
- Для надёжности на корневом view: `.environment(\.layoutDirection, .rightToLeft)` и `.environment(\.locale, Locale(identifier: "he_IL"))`.
- Тексты системных запросов разрешений (микрофон, уведомления) — на иврите в `InfoPlist.strings (he)`.
- В вёрстке только `leading`/`trailing`, никогда `left`/`right`.

**Android (Compose)**

- `android:supportsRtl="true"` в манифесте.
- Все строки — в `values/` на иврите (других языков нет). Локаль приложения принудительно `he` через `AppCompatDelegate.setApplicationLocales` + `locales_config.xml` с одним языком. Без этого на английском телефоне текст будет на иврите, но раскладка — слева направо.
- В корне Compose: `CompositionLocalProvider(LocalLayoutDirection provides LayoutDirection.Rtl)`. В окне плавающей кнопки (отдельный ComposeView) — то же самое, отдельно.
- Отступы только `start`/`end`; направленные иконки — `Icons.AutoMirrored`.

**Текст и смешанные направления (bidi)**

- Вставки латиницы, телефоны, e-mail, ссылки и имена файлов оборачиваются в Unicode-изоляты (FSI U+2068 … PDI U+2069), чтобы не скакала пунктуация.
- Любой текст от STT/LLM проходит через одну функцию нормализации (изоляты, удаление лишних LRM/RLM, пробелы вокруг пунктуации).
- Цифры — западноарабские (0–9). Дата `dd/MM/yyyy`, время 24 часа, неделя с воскресенья.
- PDF/DOCX-экспорт с правым выравниванием и флагом RTL в документе (DOCX: `w:bidi` в абзацах).

**Что зеркалить, а что нет** ([Material Design](https://m1.material.io/usability/bidirectionality.html))

- Зеркалить: стрелки «назад/вперёд», шевроны, порядок вкладок, свайпы, иконки списков с выравниванием.
- Не зеркалить: кнопки воспроизведения и прогресс аудиоплеера, часы и круговые индикаторы, микрофон, галочку, цифры, логотипы.
- Волна (waveform) диктофона относится к прогрессу медиа и тоже не зеркалится.

**Язык интерфейса**

- Обращение к пользователю без рода: инфинитив на кнопках («להקליט», «לשתף») и нейтральные формулировки в текстах, либо выбор формы обращения при онбординге.
- Шрифт: системный (SF Hebrew / Noto Sans Hebrew) или один фирменный с полной поддержкой иврита и латиницы (Heebo, Rubik, Assistant).
- Все строки — в файлах ресурсов, никаких захардкоженных строк в коде (проверяется линтером).

**Проверка:** snapshot-тесты каждого экрана на устройстве с английской и ивритской системной локалью; чек-лист RTL в шаблоне pull request; правило в CLAUDE.md проекта, чтобы AI-агенты следовали ему при генерации кода.

## Провайдеры STT и LLM (BYOK)

Пользователь выбирает пресет провайдера, вставляет свой API-ключ и нажимает «בדיקת חיבור»; приложение обращается к провайдеру напрямую с устройства. Для протоколов и для диктовки можно выбрать разных провайдеров. В каталог входят только сервисы с сильным ивритом; ElevenLabs и Deepgram исключены.

**Пресеты STT с поддержкой иврита**

| Пресет | Модели | Стриминг | Диаризация | Ограничения | Цена |
| --- | --- | --- | --- | --- | --- |
| [Gemini](https://ai.google.dev/gemini-api/docs/models/gemini-3.5-transcribe) | gemini-3.5-transcribe, gemini-3.5-transcribe-live | да, сессия до 10 мин, без диаризации | да, до 8 дикторов (от 3 — экспериментально) | файл до 1 ч, с диаризацией — до 30 мин; словарь до 1000 терминов ([документация](https://ai.google.dev/gemini-api/docs/transcribe)) | \~$0.005/мин файл, \~$0.009/мин live ([обзор](https://spokenly.app/blog/gemini-3-5-transcribe)) |
| [Soniox](https://soniox.com/docs/stt/models) | stt-async-v5, stt-rt-v5 | да, сессия до 5 ч | да | файл до 300 мин ([лимиты](https://soniox.com/docs/stt/async/limits-and-quotas)) | \~$0.10/ч файл, \~$0.12/ч стрим ([сравнение](https://soniox.com/compare/soniox-vs-openai/hebrew)) |
| [OpenAI](https://costgoat.com/pricing/openai-transcription) | gpt-4o-transcribe-diarize, gpt-4o-transcribe | да, дороже | да (diarize) | 25 МБ на запрос → нарезка | $0.006/мин, стрим $0.017/мин |
| [Groq](https://console.groq.com/docs/speech-to-text) | whisper-large-v3, whisper-large-v3-turbo | нет (очень быстрая обработка файла) | нет | 25 МБ (free) / 100 МБ (dev); подсказка до 224 токенов | $0.111/ч и $0.04/ч |
| Свой endpoint | Любой OpenAI-совместимый `/v1/audio/transcriptions`, например [ivrit.ai Whisper](https://huggingface.co/ivrit-ai) на своём GPU | нет | нет | зависит от сервера | стоимость GPU |

Точность на иврите провайдеры публикуют по своим тестам: Soniox — 1.25% WER против 3.24% у OpenAI; Google для Gemini 3.5 Transcribe даёт средний WER 2.6% по 85+ языкам ([MarkTechPost](https://www.marktechpost.com/2026/08/27/google-ai-releases-gemini-3-5-transcribe-a-speech-to-text-model-reporting-2-6-average-wer-across-85-languages/)), без отдельной цифры для иврита; Groq запускает стандартный Whisper без дообучения на иврите; модель ivrit.ai — 4.8–7.2% на разговорных наборах [лидерборда ivrit.ai](https://huggingface.co/spaces/ivrit-ai/hebrew-transcription-leaderboard). Цифры несопоставимы, поэтому в настройках есть режим «сравнить провайдеров»: одна запись отправляется во все подключённые сервисы, результаты показываются рядом.

Для Gemini есть особенность протоколов: с диаризацией файл ограничен 30 минутами, поэтому встреча нарезается на куски, и метки дикторов между кусками нужно сопоставлять (через LLM или вручную). Режим «умной транскрипции» с удалением паразитов и самоисправлений полезен для диктовки и может заменить отдельный шаг LLM-очистки.

**Пресеты LLM:** Google Gemini, OpenAI, Anthropic, Groq и любой OpenAI-совместимый endpoint (OpenRouter, свой сервер). Список моделей загружается из API провайдера, а не зашивается в код. Для протоколов — сильная модель с большим контекстом; для диктовки — быстрая и дешёвая (например, на Groq), так как задержка видна пользователю. Один ключ Gemini или Groq покрывает и STT, и LLM.

**Абстракция в коде (одинаковая на обеих платформах)**

- `SttProvider`: `capabilities` (стриминг, диаризация, макс. длительность/размер файла, словарь), `transcribeFile()`, `openStream()`.
- `LlmProvider`: `listModels()`, `complete(system, user, jsonSchema)`, `stream()`.
- Все ответы приводятся к единой модели `Transcript { segments[ speaker, startMs, endMs, text ] }`. Если провайдер не умеет длинные файлы, нарезка делается на устройстве по паузам; метки дикторов между кусками при этом не совпадают.
- Новый провайдер = один адаптер + запись в каталоге пресетов (имя, логотип, ссылка «где взять ключ», поля настроек).

**Хранение ключей:** iOS — Keychain с access group приложения (клавиатуре ключ не нужен, сетью занимается основное приложение). Android — Android Keystore + зашифрованный DataStore (Tink). Ключи не попадают в логи, бэкапы и отчёты о сбоях; в интерфейсе показываются маской.

## Архитектура iOS и Android

Два независимых нативных проекта с одинаковой структурой: UI-таргеты сверху, общий Core-модуль с провайдерами, очередью задач и хранилищем снизу. Сервер нужен только для аккаунта и синхронизации; к провайдерам AI устройство обращается напрямую. Промпты, JSON-схема протокола и каталог пресетов хранятся в общей папке `shared/` репозитория и копируются в оба проекта при сборке, чтобы поведение совпадало.

> Диаграмма «архитектура · две платформы, общие провайдеры» — в живой версии документа.

**iOS**

- Таргеты: приложение (SwiftUI), Keyboard Extension (`UIInputViewController` + SwiftUI), Widget Extension для Live Activity записи. Общий код — локальный Swift Package `SicumiCore`.
- Запись: `AVAudioSession` + `AVAudioEngine`/`AVAudioRecorder`, фоновый режим `audio` в `UIBackgroundModes`. Обработка прерываний (звонок, смена аудиоустройства).
- Загрузка файлов: фоновая `URLSession`; проверка статуса асинхронных задач — при возврате в приложение и через `BGTaskScheduler`.
- Связь клавиатуры и приложения: общий контейнер App Group + Darwin-уведомления (старт/стоп/результат готов). Клавиатура не ходит в сеть и не хранит ключи.
- Хранилище: SwiftData для метаданных, аудио и транскрипты — файлами в контейнере приложения.

**Android**

- Gradle-модули: `:app` (Compose), `:overlay` (`AccessibilityService` + плавающая кнопка на `ComposeView`), `:core` (провайдеры, данные, аудио). DI — Hilt, сеть — OkHttp (HTTP + WebSocket).
- Запись встреч: foreground service типа `microphone` с уведомлением и кнопками. Требует `FOREGROUND_SERVICE_MICROPHONE` и `RECORD_AUDIO`; запускать можно только пока приложение на экране ([Android Developers](https://developer.android.com/develop/background-work/services/fgs/service-types)).
- Очередь обработки: WorkManager с условием «есть сеть» и экспоненциальным повтором; цепочка upload → transcribe → summarize.
- Диктовка: кнопка-оверлей → `AudioRecord` → стриминг или файл → LLM-очистка → вставка через `AccessibilityService`. Запуск микрофона, когда на экране другое приложение, проверяется в прототипе: в списке исключений while-in-use ни оверлей, ни accessibility-сервис не названы ([Android Developers](https://developer.android.com/develop/background-work/services/fgs/restrictions-bg-start)), хотя Wispr Flow так работает.
- Хранилище: Room для метаданных, файлы во внутреннем хранилище приложения.

**Репозиторий:** монорепо `sicumi-v2` с папками `ios/`, `android/`, `shared/` (промпты, JSON-схемы, каталог пресетов, тексты интерфейса), `docs/`. Сборка iOS требует Mac с Xcode.

**Аккаунт и синхронизация**

- Supabase: Auth (вход через Apple и Google) + Postgres с RLS. Аккаунт необязателен: без него приложение работает полностью локально.
- Синхронизируются тексты: встречи, транскрипты, протоколы, шаблоны, словарь, сниппеты, история диктовок. Аудио по умолчанию остаётся на устройстве (опция — загрузка в Storage). API-ключи никогда не уходят на сервер.
- Схема данных с первого дня готова к синхронизации: UUID, `updatedAt`, мягкое удаление. Конфликты — «последняя запись побеждает» по полю; у протокола хранятся версии.
- Приложение бесплатное, поэтому сервер — единственная статья постоянных расходов; объём хранения ограничен текстами.

## Данные, приватность и публикация

Данные живут на устройстве; наружу уходят аудио и текст к провайдеру, которого выбрал пользователь (только после явного согласия), и тексты на сервер синхронизации — если пользователь вошёл в аккаунт.

**Модель данных**

| Сущность | Ключевые поля |
| --- | --- |
| Meeting | id, title, createdAt, durationMs, templateId, status, audioSegments\[\], participants\[\], bookmarks\[\] |
| Transcript | meetingId, providerId, model, segments\[speakerId, startMs, endMs, text\], speakerNames{} |
| Protocol | meetingId, providerId, model, templateId, contentJson, editedJson, version |
| ProcessingJob | meetingId, stage, remoteJobId, attempts, lastError, updatedAt |
| Template | id, name, sections\[\], instructions, isBuiltIn |
| Dictation | id, createdAt, rawText, cleanText, style, targetApp (только Android), durationMs |
| DictionaryEntry | term, spokenForms\[\], note |
| Snippet | trigger, text |
| ProviderConfig | providerId, kind (stt/llm), model, options, keyRef (ссылка на Keychain/Keystore) |

Версии протокола сохраняются: перегенерация не затирает ручные правки.

**Приватность**

- Экран согласия перед первой отправкой: какому провайдеру уходят данные и зачем. При смене провайдера — снова.
- Хранение аудио: настройка «удалять запись через N дней после готового протокола». После обработки файл удаляется и у провайдера, если API это позволяет.
- Диктовки (клавиатура iOS и кнопка Android): аудио не сохраняется, история текста — отключаемая. Поля паролей не обрабатываются.
- Аналитика и отчёты о сбоях — без содержимого записей, текста и ключей.
- Перед записью встречи — напоминание предупредить участников (отключаемое).

**App Store** ([App Review Guidelines](https://developer.apple.com/app-store/review/guidelines/))

- 4.4.1 — клавиатура должна давать обычный ввод символов, иметь переход к следующей клавиатуре и работать без Full Access. Поэтому на iOS есть раскладка для набора, а без Full Access голосовая кнопка объясняет, как его включить.
- 2.5.14 — явное согласие и видимая индикация записи.
- 5.1.2(i) — явное раскрытие и согласие на передачу данных сторонним AI-сервисам.
- 5.1.1(i) — политика приватности в метаданных и в приложении, сроки хранения и удаление.
- 5.1.1(v) — если есть регистрация, удаление аккаунта должно быть доступно внутри приложения.
- 4.8 — при входе через Google нужен равноценный приватный вариант входа (Sign in with Apple).
- `NSMicrophoneUsageDescription` на иврите, privacy labels (аудио, пользовательский контент).

**Google Play**

- Декларация использования Accessibility API для плавающей кнопки и экран раскрытия с явным согласием перед включением ([Play Console Help](https://support.google.com/googleplay/android-developer/answer/10964491?hl=en)).
- Декларация foreground service `microphone`: описание, последствия отложенного запуска и ссылка на видео с демонстрацией ([Play Console Help](https://support.google.com/googleplay/android-developer/answer/13392821?hl=en)).
- Форма Data safety: аудио и текст передаются третьим лицам для функциональности приложения; тексты хранятся на сервере при включённой синхронизации.
- Политика приватности и страница магазина — на иврите.

## Дизайн интерфейса

Интерфейс — ключевое требование: собственная визуальная система поверх современных нативных языков дизайна, живая анимация и сильная типографика иврита. Никаких экранов «из коробки» без проработки.

**Визуальный язык**

- iOS — [Liquid Glass](https://www.apple.com/newsroom/2025/06/apple-introduces-a-delightful-and-elegant-new-software-design/) (iOS 26: стеклянные плавающие панели и кнопки, `glassEffect` в SwiftUI) с запасным вариантом на системных материалах для iOS 17–25.
- Android — [Material 3 Expressive](https://m3.material.io/blog/m3-expressive-motion-theming) в Compose: выразительные формы, пружинная анимация, своя цветовая тема.
- Поверх — общая айдентика Sicumi: фирменный цвет и градиент для акцентов, свои иконки и иллюстрации пустых состояний, иконка приложения.

**Дизайн-система**

- Токены в `shared/design/` (цвета светлой и тёмной тем, шкала шрифтов, отступы по сетке 8, радиусы, длительности анимаций) генерируются в Swift и Kotlin из одного JSON — обе платформы выглядят как один продукт.
- Шрифт с сильным ивритом и латиницей (кандидаты: Rubik, Heebo, Assistant), крупные заголовки, межстрочный интервал подобран на реальных протоколах.
- Библиотека компонентов: карточка встречи, чип статуса, кнопка записи, волна, реплика транскрипта, задача протокола.

**Сигнатурные моменты**

- Кнопка микрофона плавно перетекает между состояниями «готова → запись → обработка → готово»; тактильный отклик на старт и стоп.
- Живая волна записи и экран записи, на котором приятно находиться час.
- Протокол «собирается» на глазах: разделы появляются по мере готовности.

**Качество:** тёмная тема с первого дня, контраст не ниже WCAG AA, поддержка увеличенного шрифта, VoiceOver и TalkBack на иврите.

**Процесс:** макеты ключевых экранов (главная, запись, протокол, кнопка диктовки, онбординг) в 2–3 направлениях → выбор направления → дизайн-система → код. Это идёт параллельно с прототипами фазы 0 и заканчивается до начала фазы 1.

## Риски и открытые вопросы

Главные риски — диктовка на обеих платформах: на Android она зависит от Accessibility API и правил запуска микрофона, на iOS — от перехода в приложение и App Review. Поэтому прототип каждой платформы — первый шаг её этапа: Android в фазе 0, iOS в начале фазы 5.

| Риск | Что может случиться | Мера |
| --- | --- | --- |
| App Review и клавиатура iOS | Правило 4.4.1 запрещает клавиатуре запускать другие приложения, кроме «Настроек»; схема Wispr Flow одобрена, но гарантии нет | Повторить схему Wispr Flow; запасной вариант — диктовка в приложении + копирование, виджет и кнопка Action |
| Сессия записи iOS в фоне | Система завершает приложение, следующая диктовка снова требует перехода | Прототип в фазе 0; измерить время жизни сессии и расход батареи |
| Микрофон из кнопки-оверлея на Android | Правила while-in-use не называют оверлей и accessibility-сервис исключением; запись может не стартовать поверх другого приложения | Прототип на Android 14–16 в фазе 0; Wispr Flow показывает, что это решаемо |
| Accessibility-политика Google Play | Отказ в публикации или требование доработок; периодические напоминания Play пользователям о доступе | Использовать API только для кнопки и вставки по явному нажатию; декларация, экран раскрытия, видео |
| Длинная запись на Android | Прошивки Samsung, Xiaomi и др. убивают фоновые процессы и отключают accessibility-сервисы | Запись сегментами, восстановление после сбоя, инструкция по оптимизации батареи, проверка разрешения при запуске |
| BYOK для публичной аудитории | Большинство пользователей не знают, что такое API-ключ | Пошаговые инструкции на иврите по каждому провайдеру; один ключ Gemini или Groq покрывает STT и LLM |
| Диаризация на иврите | Путаница дикторов в зашумлённых помещениях; у Gemini — лимит 30 минут и экспериментальная атрибуция от 3 дикторов | Бенчмарк на реальных записях; ручное переименование и объединение дикторов |
| Галлюцинации в протоколе | LLM придумывает решение или ответственного | Каждое решение и задача ссылается на тайм-код транскрипта; неизвестные поля остаются пустыми |
| Стоимость для пользователя | Непрозрачные расходы на его ключе | Оценка стоимости каждой встречи и счётчик минут за месяц |
| Сервер при бесплатном приложении | Расходы на синхронизацию растут с числом пользователей | Синхронизировать только тексты; лимит объёма на аккаунт; мониторинг расходов |

**Решения**

- Монетизация: бесплатно.
- Название в сторах: Sicumi.
- Минимальные версии: iOS 17+, Android 8.0+ (API 26).
- Аккаунт и синхронизация между устройствами: нужны (фаза 3 roadmap).
- Планшеты: не в первом релизе.
- Провайдеры STT: Gemini, Soniox, OpenAI, Groq, свой endpoint; ElevenLabs и Deepgram исключены.
- Android: только плавающая кнопка диктовки, без своей клавиатуры.
- Порядок разработки: сначала Android до релиза, iOS — после.
- Дизайн: направление C «Смелые формы» — фиолетовый #4B2FD6 + мандарин #FF8A3D, шрифты Secular One и Heebo, форма «капля» для главного действия.

**Открытые вопросы**

- [ ] Формат протокола по умолчанию — ждём образец в PDF.
- [ ] Нужно ли сквозное шифрование текстов на сервере синхронизации?
- [ ] Написание названия на иврите для иконки и страницы в сторах (или только латиница Sicumi).

## Roadmap

Сначала Android целиком, до релиза в Google Play; работа над iOS начинается после этого. iOS-версия строится на уже готовых дизайн-системе, промптах, сервере синхронизации и схеме данных, поэтому общие части сразу делаются платформенно-независимыми (папка `shared/`). Сроки не заданы.

> Диаграмма «roadmap · Android → iOS, 8 фаз, 2 гейта» — в живой версии документа.

Протоколы идут раньше диктовки: они строят дизайн-систему, RTL-каркас, слой провайдеров и запись, которые диктовка затем использует. Синхронизация идёт после основных модулей, но схема данных готова к ней с фазы 1.
